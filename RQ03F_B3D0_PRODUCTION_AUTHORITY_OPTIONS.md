# RQ-03F-B3-D0 — Production High-Water Authority Options

**Decision status: `PROPOSED — OWNER_DECISION_REQUIRED`.** This comparison prepares an Owner decision only. No cloud account, host, credential, database, Witness, TPM, or production Authority was selected or provisioned.

## Decision context

C3 defines a `HighWaterAuthority` interface (`read_current`, `prepare_transition`, `verify_transition_authorization`, `commit_transition`, `abort_transition`, `read_transition`) and treats the Authority compare-and-swap as the trust transition's linearization point. The interface is in `教案生成器/lesson-plan-docx-generator/scripts/rq03f_monotonic_trust_ledger.py` at master `bc109e30e3223a9cb780f20c13c73963f356866e`. C3 has no production adapter. Its hosted Witness is temporary, synthetic, and branch-controlled.

Any candidate must keep Authority state outside the Operator machine's administration, disk, snapshot, and backup rollback domain. It must atomically enforce the expected sequence/state digest, fencing token, pending transition, authorization purpose, actor and approver separation, current role validity/revocation, proposed state digest, and Index SHA/revision. A Prepare reservation does not authorize a later Commit by itself. Unknown Commit status remains `RECOVERY_REQUIRED`; the adapter must reconcile by transition ID and must not retry a side effect into success.

## Recommendation for Owner consideration

**Preferred for evaluation: Option B, an Owner-controlled Spanner-backed Authority in a separate cloud administration domain. `PROPOSED — OWNER_DECISION_REQUIRED`.** The C3 critical primitive is atomic, current, purpose-bound CAS with a durable ordered history. Spanner documents serializable, externally consistent read-write transactions that can provide the needed database transaction primitive, with lower service-hosting burden than a self-managed quorum. This does not mean that a product feature alone establishes production trust. A production adapter, independent cloud IAM, Owner-controlled authority identity, external recovery checkpoint, append-only retention, tests and target-host evidence are still required.

**Fallback for an Owner without an approved Spanner/cloud domain: Option A, a separately administered Linux Witness backed by a quorum store. `PROPOSED — OWNER_DECISION_REQUIRED`.** This preserves the existing Linux integration model but adds greater operational responsibility. A single-host file or SQLite Witness is not recommended as a production anti-rollback root because its host/storage/backup administrator can replace the entire state domain.

**Option C is supplemental only.** Do not treat a TPM counter as a Ledger or as a standalone `HighWaterAuthority`. The TCG command increments a scalar NV index; the C3 contract needs much more than a scalar counter.

## Mandatory proof before either A or B can be accepted

1. Owner-controlled service identity, administrative domain, trust roots and role/authorization registry; no Candidate or Operator can alter those inputs.
2. Authenticated Operator-to-Authority channel with mutual identity checking, defined rotation/revocation, and no caller-supplied principal as authority.
3. Linearizable `read_current`; unique transition IDs; conditional Prepare against expected state; expiry-bound reservation; Commit atomically revalidates role/purpose/actor/approver/revocation/fencing and performs one CAS.
4. Authority-owned ordered history with sequence, previous head, Index SHA/revision, policy/Profile/Build/Generation binding, revocation digest, purpose and authorization references. Duplicate IDs and mixed purposes fail closed.
5. Read-after-uncertain-commit by transition ID. A missing ACK never authorizes a second business write; unknown state becomes `RECOVERY_REQUIRED`.
6. Backup restore to a quarantined identity/database. Recovered state cannot become active until it equals or extends the latest independent Owner-adopted checkpoint. No reset, old-snapshot activation, epoch rollback or old authorization re-signing.
7. Separately managed service availability, health monitoring, audit retention, key/role revocation, incident response and change approval.
8. Independent Owner acceptance on the target host before Production Trust or any protected write is considered.
