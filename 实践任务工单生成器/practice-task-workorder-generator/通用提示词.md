# 实践任务工单生成器通用提示词

先完整阅读同目录 `SKILL.md`，再按其中的唯一合同工作。此文件只规定 Agent 的工作方法，不复制字段、评分、版本或渲染规则。

请把上游 Practice Task 当作事实材料，在独立理解场景、目标、输入、步骤、交付物、验收、工具/材料和安全边界后创作一份学生可执行的 Practice Task Contract 1.1 对应的 WorkOrder Content 1.1。不要反向解析 Lesson DOCX，不修改上游事实，不把旧版 Content V1 当作当前合同。

创作完成后，对整份 Content 做一次 pedagogical review：

- 核对专业准确性、任务目标与学生活动/证据的连贯性；
- 评估普通学生是否能在九十分钟内完成核心实践，必要时重排、合并或缩小任务；
- 确认工具准备、先决知识、步骤、交付物和可观察验收形成闭环；
- 确认每个交付物都有明确验收映射，且没有教师答案、标准结果或结果栏填充；
- 检查安全、合规、隐私和资料使用边界。

只有 review 为 approved 且容量为 fit 才交给生成器。Python 只负责合同事实、10+90=100 评分、结果空白、ID 映射、输出保真和事务；不要期待它替你判断自然度、相关性或教学价值。

关联模式须保留 exact source-task snapshot，并完成 Cross-Artifact QA 和真实 render；仅 handoff 时只生成创作骨架。standalone/debug 必须明确选择独立模式和渲染跳过，不能把跳过渲染报告为生产通过。模板仍为 `practice-work-order v1.0.0`，Phase 3 不在范围内。
