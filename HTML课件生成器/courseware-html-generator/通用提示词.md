# HTML 课件生成器通用提示词

你负责把用户提供的教材、PPT、讲义、教案或课程资料转成可授课的 `Courseware Content Contract 1.1`。先做公开 Teaching Blueprint，再创作 Draft Contract；不要直接手写最终 HTML、CSS 或 JavaScript，交给 Skill 内置 renderer。

## 先做蓝图

从资料中确认课程目标、授课对象、前置知识和可能弱项。蓝图至少包含：`course_goal`、`session_minutes`、`prepared_minutes`、`core_minutes`、`extension_minutes`、`audience_profile.level/prior_knowledge/likely_weaknesses`、`learning_units`、`canonical_facts`、`not_yet_taught`、`teaching_sequence`、`visual_needs`、`activity_needs`、`likely_misconceptions` 和 `prepared_extension_plan`。每个跨模块复用的事实还要保留 `source_refs`、`evidence` 和 `verification`；按事实类型区分 direct text、structured data、computed、code-derived、relationship/model 与 pedagogical inference。未知事实标记为未知，不用常识填充成资料结论；蓝图不能包含 chain-of-thought 或私有推理。

`prepared_minutes` 可以比课堂 `session_minutes` 多。此时明确核心路径与扩展路径，90/120 的情形就是 90 分钟必讲内容加 30 分钟教师可展开内容；扩展内容必须有 `title`、`minutes`、`content`、`activity`、`use_when`，教师版显示“备用内容 / 讲得快时使用”。不要用根级时长掩盖实际页计划。

## 合同创作

每个 `learning_unit` 至少被一页 `learning_unit_ids` 覆盖。每页有稳定 `id`、合法 `layout`、blocks、`lecture_minutes`、`activity_minutes`、`suggested_minutes`、完整 `teaching_intent` 和连续 `speaker_script`。`activity_minutes > 0` 时必须有可执行 `activity_plan`，包含 type、teacher_prompt、student_action、expected_artifact_or_response、check_method 和分段分钟数；简单问题不能单独占据长活动。讲稿自然完成进入/承接、核心解释、当前图/表/代码说明、例子、易错点、提问与接话、过渡；不要机械套八段、重复整段或用提示框凑长度。

讲稿有效容量低于约 80 字/讲解分钟是教学失败信号，约 120–160 字/分钟是正常目标区间。结构校验与教学审查分开：正常区间不是 schema 硬门槛，短稿不能被“讲一下定义”替代。

学生页面不出现“120分钟”、备课/学生/教师版、来源、原资料、内部 ID、答案或教师提示。SVG 必须承担图、流程、状态、架构或对比的解释；练习答案默认隐藏，stepper 要可前后/重置。

## 生成与复核

新生成先运行 `source_truth_validator.py --mode strict` 与 `activity_time_reviewer.py --mode strict`，两者通过后再执行合同校验、教学审查和 renderer；Practice 只有在 Courseware 时间证据通过后才能生成。历史 1.0/旧 fixture 回归才允许显式 `migration-trust`。

```text
python scripts/teaching_blueprint.py --blueprint-json <blueprint.json> --json
python scripts/repair_courseware.py --content-json <draft.json> --output-json <repaired.json> --max-rounds 2
python scripts/render_courseware.py --content-json <repaired.json> --output-dir <out> --replace --json
python scripts/validate_courseware.py --content-json <repaired.json> --student-html <out>/student.html --teacher-html <out>/teacher.html --json
```

自动修复最多两轮，只能从同一合同推导学习链接、意图字段和页级时长合计；缺失事实、扩展方案或讲稿必须回到 Agent 重新创作。失败不覆盖正式输出。

最后用真实 Chrome/Edge 打开 `file://` 学生页：点击背景、标题、普通卡片、SVG、代码区，检查上下滚轮和一次 wheel 不多跳页；点击答案、stepper、投影增强等控件时不得额外翻页。

## G3.2 Courseware Gold 正式完整性规则（Skill 1.2.1）

Courseware 默认使用 `session_delivery_mode: "theory-led"`。为每个有活动分钟的页面声明 `activity_role`：`teacher-led-demonstration`、`guided-whole-class-reasoning`、`short-student-check` 或 `student-independent-practice`。如果另有 Practice，理论课活动由教师演示、全班推理和短检查构成主线；边界审查比较活动分钟而不是套固定比例。

讲稿以 80 个有效字符/讲解分钟为硬下限，以 120–160 为正常生成目标。先完成 blocks、教学意图、视觉/代码/表格和 lecture_minutes，再做 script planning，最后写完整 speaker_script。讲代码要说关键行/结构，讲表格要说列/行/比较，讲 SVG 要说节点/箭头/变化；禁止复制、套话和重复填充。Gold 批量门禁会排除封面、目录、极短总结和扩展页，并检查核心页密度、median、低于正常目标比例、近下限比例、重复 n-gram/段落和视觉解释覆盖。

新生成必须先读取 `docs/planning-integrity-v1.md`，遵循 Integrity Contract 1.0；Content Contract 仍为 1.1。使用 strict evidence mode；migration-trust 仅用于历史回归。先验证草稿，再渲染最终内容，不手工修补已生成包。所有行为、资产、公式和规划证据按文档保存，自动评分不得掩盖 DEGRADED 或不可用检查。
