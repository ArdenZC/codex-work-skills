# Claude Code 入口（Lesson Skill 2.2.1）

若明确 `practice_work_orders=true`，Lesson Agent 完成 Lesson QA/DOCX 后必须检测并调用 WorkOrder Skill Agent，实践学时为正偶数、每个 Practice Task 固定 2 学时、任务数与 WorkOrder 数均为 `practice_hours / 2`，统一交付 Lesson 与 WorkOrder；不可用时明确 `实践任务工单生成器当前不可用，已保存实践任务数据文件，可在工单生成器可用后继续生成。`，不得由 Lesson Python 生成工单。若明确 false，实践学时只进入课程总账，不生成 contract、handoff、WorkOrder 或实践侧额外文件。

开始任务前读取 `SKILL.md` 和 `通用提示词.md`。它们是教案生成器的唯一行为规范：当前为 Lesson Skill 2.2.1，默认使用 Content Contract 2.2（兼容读取 2.1/2.0）。先进入 `INTAKE_PENDING`，用中文一次性确认课程名称、专业、授课对象、总课时；同一摘要显示理论/实践课时、理论与实践组织方式（全部理论、全部实践、分段组织或综合组织）、单课默认 2 学时、教材、辅助资料和实践任务工单偏好。四个核心字段缺失时显示“待补充”，总课时必须由用户明确提供；未明确提供的结构显示“待确认”，不按 50/50、综合式或“否”推断；推断的专业/对象标注“当前理解 / 如不准确请修改”。教材建议确认但不是阻断字段。确认后进入 `INTAKE_CONFIRMED`，按已确认的工单选择完成课程级 outline、必要时的 Practice Task Contract、完整 JSON、Content/模板/输出 QA，最后原子提交 DOCX，不能再问模板、输出目录或是否开始 DOCX。2.2 Lesson DOCX 只承载理论，实践课时不进入 Lesson DOCX；仅在明确 true 时由 Practice Task/WorkOrder handoff 表达，实践任务固定 2 学时且数量为 `practice_hours / 2`，明确 false 时不产生 handoff。理论课次数量按默认单课课时向上取整，余数保留。`course_materials.textbook` 与 `reference_pool` 分离，教材默认不写入 references；每课只用 `reference_ids`，references 是可阅读/引用的文献或文档来源，resources 是工具/设备/环境/材料，合法 reference 可跨课复用，同课重复 ID、纯资源名和占位文献不可用。优先使用国内出版物、高校资料和标准，不得为了降重复率虚构书目信息。不要使用 sparse input、不要手工改写模板或在教案中写入 QA/AI 说明。
