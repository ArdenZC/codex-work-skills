## Graph facts checked

The lesson uses the issue's fixed undirected graph with vertices A–E and edges
AB, AC, BC, CD, CE, DE. Neighbors are visited alphabetically from D.

- DFS: `D → C → A → B → E`
- BFS: `D → C → E → A → B`
- Removing any one edge leaves the graph connected.
- Removing CD and CE leaves components `{A, B, C}` and `{D, E}`.

`tests/test_issue71_graph_facts.py` executes the adjacency-list, traversal, and
connectivity checks, including the invalid single-edge claim and the corrected
two-edge example.

## Visual result and limits

Canonical generation, template/output validation, and LibreOffice render smoke
passed for both versions. The same input produced seven pages with Template
1.1.2 and five pages with Template 1.1.3. Manual inspection of the baseline
evaluation pages 2–4 and last page 7 confirmed the narrow 1.75 cm remarks column
and split remarks. With Template 1.1.3, the remarks column is 4.88 cm; evaluation
rows remain intact across pages 2–3, the longest criterion is fully visible, and
scores and remarks are readable. Page 3 starts with a complete evaluation row;
the nested table header does not repeat there, so read pages 2 and 3 in sequence.
The new last page (page 5) contains the final teaching content and all reflection
entries, with no extra blank page. Full-page captures and retained PDFs are in
the evidence files above.

The exact 14 × 4 evaluation matrix, merged-cell topology, all 13 scores, all 13
remarks, and bookmark signatures compare equal between the two generated DOCX
files. Both outputs preserve 70 required semantic anchors. The committed
synthetic input has total score 88.5 and a 21.5 score in the 25-point row; a
separate transient test verifies a 23.5 cell without changing the committed
input.

The v1.1.2 template and manifest remain byte-for-byte unchanged. The new v1.1.3
version changes the evaluation column widths and keeps each evaluation row
together across page breaks. No remark was shortened, no font was shrunk, and no
page cap was added. The render QA report records the automated visual status as
`not_evaluated`; the manual visual findings are recorded in
