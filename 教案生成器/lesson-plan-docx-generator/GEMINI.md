# Gemini CLI 入口（Lesson Skill 2.2.2）

若明确 `practice_work_orders=true`，Lesson Agent 完成 Lesson QA/DOCX 后必须检测并调用 WorkOrder Skill Agent；实践任务固定 2 学时，任务数与 WorkOrder 数均为实践学时除以 2，统一交付 Lesson 与 WorkOrder；不可用时明确 `实践任务工单生成器当前不可用，已保存实践任务数据文件，可在工单生成器可用后继续生成。`，不得由 Lesson Python 生成工单。若明确 false，实践学时只进入课程总账，不生成 contract、handoff、WorkOrder 或实践侧额外文件。

先读取 `SKILL.md` 和 `通用提示词.md`，遵循 Lesson Skill 2.2.2、Content Contract 2.2（兼容 2.1/2.0）和 QA 流程。正式规划前进入 `INTAKE_PENDING`，用中文一次性确认课程名称、专业、授课对象、总课时，并在同一摘要显示理论/实践课时、理论与实践组织方式（全部理论、全部实践、分段组织或综合组织）、单课默认 2 学时、教材、辅助资料和实践任务工单偏好；四个核心字段缺失时显示“待补充”，总课时必须由用户明确提供；未提供的结构显示“待确认”，不按 50/50、综合式或“否”推断，推断的专业/对象标注“当前理解 / 如不准确请修改”。教材建议确认但不是阻断字段，默认单课 2 学时不单独追问。用户确认后进入 `INTAKE_CONFIRMED`，将确认结果冻结到 `confirmed_course_info`，正文 Agent 不得重写课程名称、专业、授课对象或课时；有联网能力时必须先实际检索真实公开资料，再建立 `reference_pool`。不再询问模板、输出目录或是否开始生成。课程级 outline 必须先于逐课生成；2.2 Lesson DOCX 只承载理论，实践课时不进入 Lesson DOCX，只有明确 true 时才生成 Practice Task/WorkOrder handoff，且每任务固定 2 学时。正文、实施、评价备注和反思由 JSON 提供，Python 只格式化、校验和写入受保护模板。`course_materials.textbook` 与 `reference_pool` 以及课次 `resources` 彻底分离，教材、PPT、课件、案例和内部教学资源不得进入 references；每课只用 `reference_ids`，references 是可阅读/引用的文献或文档，resources 是工具/设备/环境/材料，合法 reference 可跨课复用，但同课重复 ID、纯资源名和 generic 占位来源必须失败。资料不足时少写，不得编造书目信息；formatter 删除机械“聚焦：xxx”等主题尾缀。不要接受 sparse input、静默截断或把内部 QA 信息写入 DOCX。
2.2.2 参考文献还必须保留真实责任者信息：正式出版物写作者/编者、出版社和年份；在线课程写责任教师/课程团队、开课高校和平台/出版社，不得仅以平台名称充当责任者。优先混合正式出版物与高校公开课程，并继续排除当前课程教材。
