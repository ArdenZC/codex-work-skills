# Gemini CLI 入口（Lesson Skill 2.2.1）

若明确 `practice_work_orders=true`，Lesson Agent 完成 Lesson QA/DOCX 后必须检测并调用 WorkOrder Skill Agent；实践任务固定 2 学时，任务数与 WorkOrder 数均为实践学时除以 2，统一交付 Lesson 与 WorkOrder；不可用时明确 `实践任务工单生成器当前不可用，已保存实践任务数据文件，可在工单生成器可用后继续生成。`，不得由 Lesson Python 生成工单。若明确 false，实践学时只进入课程总账，不生成 contract、handoff、WorkOrder 或实践侧额外文件。

先读取 `SKILL.md` 和 `通用提示词.md`，遵循 Lesson Skill 2.2.1、Content Contract 2.2（兼容 2.1/2.0）和 QA 流程。正式规划前进入 `INTAKE_PENDING`，用中文一次性确认课程名称、专业、授课对象、总课时，并在同一摘要显示理论/实践课时、理论与实践组织方式（全部理论、全部实践、分段组织或综合组织）、单课默认 2 学时、教材、辅助资料和实践任务工单偏好；四个核心字段缺失时显示“待补充”，总课时必须由用户明确提供；未提供的结构显示“待确认”，不按 50/50、综合式或“否”推断，推断的专业/对象标注“当前理解 / 如不准确请修改”。教材建议确认但不是阻断字段，默认单课 2 学时不单独追问。用户确认后进入 `INTAKE_CONFIRMED`，按已确认的工单选择完成 outline、必要时的 Practice Task Contract、JSON、QA 和 DOCX，不再询问模板、输出目录或是否开始生成。课程级 outline 必须先于逐课生成；2.2 Lesson DOCX 只承载理论，实践课时不进入 Lesson DOCX，只有明确 true 时才生成 Practice Task/WorkOrder handoff，且每任务固定 2 学时。正文、实施、评价备注和反思由 JSON 提供，Python 只格式化、校验和写入受保护模板。`course_materials.textbook` 与 `reference_pool` 分离，教材默认不进入 references；每课只用 `reference_ids`，references 是可阅读/引用的文献或文档，resources 是工具/设备/环境/材料，合法 reference 可跨课复用，但同课重复 ID、纯资源名和 generic 占位来源必须失败。参考资料优先国内出版物、高校资料、国家/行业/职业标准和国内权威文件；禁止为查重虚构书目信息。不要接受 sparse input、静默截断或把内部 QA 信息写入 DOCX。
