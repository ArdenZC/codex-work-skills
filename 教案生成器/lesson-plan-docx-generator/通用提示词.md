# 教案生成器通用提示词 2.2.3

请先完整阅读同目录 `SKILL.md`，再读取当前会话、用户附件和课程资料。此文件只规定 Agent 的工作方法与审阅顺序；字段、版本、课时和输出门禁以 `SKILL.md` 及其机器合同为准。

先进入 `INTAKE_PENDING`，用中文一次性展示并确认课程名称、专业、授课对象、总课时、理论课时、实践课时、理论与实践组织方式、单课课时、使用教材、辅助参考资料和是否同时生成实践任务工单。不要把内部字段名当作用户问题。确认后冻结课程基本盘，先做整门课程 outline，再写逐课 Content Contract 2.2；确认后不再询问 outline、项目/任务、评分、模板、输出目录或是否开始生成。

资料判断遵循“真实可核验优先、无法核验不补写”：教材、课件、PPT、案例和设备只作为课程资料或 resources；可引用文献/文档才进入参考文献。需要外部来源时实际检索并保留证据；没有可靠外部来源时如实保持空 reference pool，不虚构作者、出版社、ISBN、年份或标准编号。教材是建议确认但不是必填（recommended, not required）。课程级参考资料规划可在 Agent 内部称为 `course_reference_pool`，落盘遵循 canonical contract。

逐课教学内容必须独立设计，并说明前置知识、目标、活动、学生证据、产出、下一课衔接和案例策略。每课九阶段要形成“内容—教师活动—学生活动—证据/产出—设计意图”链；1 学时课要实质性少于 2 学时课。生成前由 Agent 逐课审阅专业准确性、目标—活动—证据、阶段连贯性、课时容量、递进关系和参考文献相关性，发现问题先重写 JSON，不让 Python 添加教学句子。

只有用户明确选择生成实践任务工单时，才按 `SKILL.md` 生成 Practice Task Contract 1.1，并由 WorkOrder Skill Agent 独立创作和审阅工单；Lesson 的实践任务反向字段保持空数组。不可用时交付 handoff 和明确的不可用说明，不伪造工单 DOCX，不在 Lesson 生成器中 subprocess 调用 WorkOrder Python。

最后按合同完成 Input/Content QA、candidate DOCX、Output QA、真实 render smoke 和原子提交。`--render` 只产生 smoke 证据；人工视觉检查需单独完成。所有正式输出、QA 和版本状态以当前 `SKILL.md` 为准，旧版兼容只在显式 legacy 路径使用。
