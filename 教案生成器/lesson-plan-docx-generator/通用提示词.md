# 教案生成器通用提示词 2.3.1

先完整阅读同目录 `SKILL.md` 和课程合同。新任务默认写 Lesson Content Contract 2.3；已有 Content 2.2 必须维持原语义，不静默升级。Teaching Exemplar Benchmark 继续使用独立 sidecar，不扩展 Lesson schema。

一次性用中文确认课程名称、专业、授课对象、总课时、理论/实践学时、组织方式、单课学时、教材、参考资料和是否需要实践任务工单。确认后冻结事实并完成全课程 outline，再写逐课正文、来源证据和 pedagogical review。不可确认的来源不得补造。

按交付方式规划 Lesson：`theory_only`、`integrated_lessons`、`hybrid` 覆盖全部 `total_hours`；`split_lessons` 只覆盖 `theory_hours`；`practice_only` 保持零 Lesson。整课数量是覆盖学时除以默认单课学时向上取整，尾数保留。Integrated 只能用 integrated Lesson；hybrid 可混用 theory/practice/integrated。逐课和课程理论/实践/总账必须准确相加，按真实课程安排分配，不为凑整机械平分。

64 总学时、32 理论、32 实践、默认每课 2 学时的 integrated 课程必须写 32 个 Lesson、覆盖 64 学时。不要因为用户不需要 WorkOrder 就删掉 Lesson 内实践：工单 false 仍是 32 Lesson/0 Practice Task；工单 true 仍是 32 Lesson，并提供 16 个 2 学时 Practice Task/WorkOrder。工单是 Lesson 实践环节的配套执行材料，不增加课程总时数。Content 2.2 的历史理论-only 语义不变；Content 2.3 split 也继续仅覆盖理论学时，practice_only 继续无 Lesson。

只有用户明确需要工单时才写 Practice Task Contract 1.1。Content 2.3 中，工单关闭时 Lesson 的 `practice_task_ids` 全为空；开启时 theory Lesson 为空，实践承载的 integrated/practice Lesson 与任务双向链接。Split 继续使用 task→theory 单向链接。WorkOrder Skill Agent 独立创作工单；Lesson Python 不得调用其 Python 或伪造工单文件。

Benchmark 按 `SKILL.md` 固定流程处理：Curator 独占完整 Catalog/Split，Author/Reviewer 每课只接收选定 Cards；逐课 Review、课程汇总、Authorization claims 和 Artifact manifest 保持全链校验。Authorization 1.0 支持 Content 2.2/2.3 并记录实际合同版本。Round 2 必须是真实语义修订并更新对应的 review history/provenance。

正文、九阶段活动、学生证据、评价和反思由 Agent 创作。Python 仅校验确定性字段、课时账、来源、模板、输出、事务和渲染证据，不为内容补写 prose，也不判教学质量。按 `SKILL.md` 完成 Content QA、模板/输出 QA、请求的 render smoke 与 Acceptance 证据。
Agent 只创作 Lesson Content JSON、Practice Task handoff data、Benchmark sidecars/evidence 与 pedagogical review。最终 Lesson DOCX 只允许由 canonical generate_lesson_plans.py 基于 Template 1.1.2 生成并通过 Output QA、所需 retained render、artifact manifest verification 与 Acceptance；任一 generator/template validation/Output QA/manifest verification 失败即 BLOCKED，禁止手工创建、修改、修补或绕过。完整禁令见 SKILL.md「最终 Lesson DOCX 的不可绕过生产边界」。

## Lifecycle candidate / practice_only 路由

LIF-01～05 已合并，当前仍是 Lesson Skill **2.3.1 candidate / pre-2.4 release state**，尚未发布 2.4 Stable。Canonical Lesson lifecycle 的完整生产路径为：

```text
Source Truth → Quality Eligibility / Benchmark Preparation → Content → Preproduction QA → Benchmark disposition / Review → Deterministic Teacher Review Packet → Human Teacher Review → Production Authorization → Canonical Generator → Artifact QA → Deterministic Visual Review Packet → Human Visual Review → Acceptance 3.0 → ACCEPTED
```

两处 Human Review 都必须由外部人工提供；synthetic evidence 只证明 contract closure，不代表真实教学质量通过。`production_pass` 是 generator 产物事务结果，不能替代 lifecycle `ACCEPTED`。

Content 2.3 的 `practice_only → lessons=[]` 继续合法。Canonical Lesson pipeline 的 PREVIEW/PRODUCTION 均只适用于至少 1 个真实 Lesson；`bind-content` 在绑定 Content 或推进 AUTHORING_COMPLETE 前明确拒绝 zero-Lesson，不能伪造 Lesson、Teacher Packet/Review 或 Lesson DOCX。Standalone Content tooling/direct generator 的历史行为保持兼容。需要纯实践材料时交给 Practice Task / WorkOrder Skill；Lesson Acceptance 3.0 不用于证明纯实践工单的教学验收，也不宣称 WorkOrder 已有等价生命周期。工单仍只在用户明确需要时创作。

完整边界与剩余发布事项见 `SKILL.md` 的 Lifecycle candidate / practice_only 路由；完整引擎包含对应的 pipeline、Acceptance 和 Release Closeout 文档。
