# 教案生成器通用提示词 2.3.0

请先完整阅读同目录 `SKILL.md`，再读取当前会话、用户附件和课程资料。此文件只规定 Agent 的工作方法与审阅顺序；字段、版本、课时和输出门禁以 `SKILL.md` 及其机器合同为准。Skill 2.3.0 的 Teaching Exemplar Benchmark 只使用独立 sidecar，不扩展 Lesson Content 2.2。

先进入 `INTAKE_PENDING`，用中文一次性展示并确认课程名称、专业、授课对象、总课时、理论课时、实践课时、理论与实践组织方式、单课课时、使用教材、辅助参考资料和是否同时生成实践任务工单。不要把内部字段名当作用户问题。确认后冻结课程基本盘，先做整门课程 outline，再写逐课 Content Contract 2.2；确认后不再询问 outline、项目/任务、评分、模板、输出目录或是否开始生成。

资料判断遵循“真实可核验优先、无法核验不补写”：教材、课件、PPT、案例和设备只作为课程资料或 resources；可引用文献/文档才进入参考文献。需要外部来源时实际检索并保留证据；没有可靠外部来源时如实保持空 reference pool，不虚构作者、出版社、ISBN、年份或标准编号。教材是建议确认但不是必填（recommended, not required）。课程级参考资料规划可在 Agent 内部称为 `course_reference_pool`，落盘遵循 canonical contract。

逐课教学内容必须独立设计，并说明前置知识、目标、活动、学生证据、产出、下一课衔接和案例策略。每课九阶段要形成“内容—教师活动—学生活动—证据/产出—设计意图”链；1 学时课要实质性少于 2 学时课。按 `SKILL.md` 的 Teaching Exemplar Benchmark 流程由 Curator 独占完整 Catalog/Split 并生成物理隔离 A/B Packs；运行时 Author 和 Reviewer 只收到本课已选 Cards，不接收完整 Pack。Authoring Selection 绑定既有 outline digest；Reviewer 只收到最终 pedagogical-reviewed Lesson Content、Source Truth 摘要、已选 B Cards、Holdout Selection 和 rubric。Holdout Selection 绑定 Round 1 Lesson Content 精确字节；最多两轮使用同一冻结 benchmark run、B Pack 和 Holdout Selection，并完整复验 Round 1 Content、课程总结和逐课 Review。实质修订必须同步更新 Content 2.2 `pedagogical_review` history 与 provenance；只改 JSON 排序不算修订。Benchmark 选择、逐课 Review、课程总结、Authorization 和 provenance 只写在 sidecar，不写进 Lesson JSON；不可用或无相关案例时如实标记，不能添加无关案例。Authorization claims 由共享 deterministic helper 从全 evidence 推导；builder 不接受 `REVISION_REQUIRED`。generator 的 required mode，或 optional mode 中提供 Authorization 时，都要传入 Catalog、Split、A/B Packs、A/B Selections、课程 Review、逐课 Review shards；Round 2 另传 Round 1 Review、shards 和 Content。generator 与 Acceptance 都重新导出 claims 并比较 Artifact Authorization 与 manifest；`2.3-benchmark-linked` 表示证据链完整绑定，不表示教学通过。生成前由 Agent 逐课审阅专业准确性、目标—活动—证据、阶段连贯性、课时容量、递进关系和参考文献相关性，发现问题先重写 JSON，不让 Python 添加教学句子。

只有用户明确选择生成实践任务工单时，才按 `SKILL.md` 生成 Practice Task Contract 1.1，并由 WorkOrder Skill Agent 独立创作和审阅工单；Lesson 的实践任务反向字段保持空数组。不可用时交付 handoff 和明确的不可用说明，不伪造工单 DOCX，不在 Lesson 生成器中 subprocess 调用 WorkOrder Python。

最后按合同完成 Input/Content QA、candidate DOCX、Output QA、真实 render smoke 和原子提交。`--render` 只产生 smoke 证据；人工视觉检查需单独完成。所有正式输出、QA 和版本状态以当前 `SKILL.md` 为准，旧版兼容只在显式 legacy 路径使用。
