## 生产边界

- 先一次性确认课程基本盘，再生成完整课程 outline 和逐课内容；未确认的结构保持待确认，不自动推断。
- Content 2.3 按 delivery mode 计算 Lesson coverage：`theory_only`、`integrated_lessons`、`hybrid` 覆盖 `total_hours`；`split_lessons` 覆盖 `theory_hours`；`practice_only` 沿用零 Lesson 行为。Content 2.2 继续遵循旧理论 Lesson 边界。
- 64 总学时、32 理论、32 实践、默认每课 2 学时的 integrated 课程生成 32 份 Lesson、覆盖 64 学时；不需要 Practice Task/WorkOrder 时仍是 32 份 Lesson，需要时再配套 16 份 2 学时实践任务/工单，不增加总课时。
- 每课按 `before=10` 分钟、`in_class=hours×45` 分钟、`after=15` 分钟记录，课外时间不计入课程学时；1 学时课也必须是 10/45/15。
- `course_materials.textbook`、lesson `resources` 和 `reference_pool` 分离。书籍作者/编者、书名、出版社必填，年份可选；`no_verified_external_source` 表示没有核实到公开来源，可空池，也可保留有真实出处的用户提供正式资料，不写占位来源。
- 需要实践工单时，只从已确认课程基本盘生成 Practice Task Contract 1.1；Content 2.2 保持 task→theory Lesson 的单向关联，Content 2.3 integrated/practice Lesson 与配套 Practice Task 双向关联。
- Practice Task 与 WorkOrder 一一对应，每个 WorkOrder 固定 2 学时；关联模式保留完整 `source_task_snapshot`。
- 教学语义由 Agent 负责设计、审查和必要重写；Python 只做 schema、事实、小时、ID、精确重复、模板映射、输出和渲染等确定性门禁。
- 未执行 render 时可结构通过但不能生产通过；只有真实渲染和保留 PDF 的哈希/页数核验通过，才报告 `production_status=production_pass`。生产渲染失败或跳过输出校验都不能报告生产通过。

## 使用入口

```powershell
python scripts/install.py --help
python scripts/doctor.py --help
python scripts/generate_lesson_plans.py --help
```

历史 Content 2.1/2.0 只走显式 `--legacy` 兼容路径；新会话默认使用 Content 2.3 与 Practice Task Contract 1.1，已有 Content 2.2 输入按原合同校验。
