# 教案生成器 2.1.0

教案生成器用于批量生成、整理和校验项目化中文课程教案 DOCX。

## 当前版本

| 项目 | 当前版本 |
| --- | --- |
| Lesson Skill | **2.1.0** |
| Content Contract | **2.1** |
| 默认 Word 模板 | `lesson-plan v1.1.2` |
| 正式验收平台 | Windows、macOS |

这三个版本彼此独立：**Skill 已升级到 2.1.0，Content Contract 为 2.1（兼容读取 2.0），Word 模板仍是 v1.1.2。** Skill 版本表示整体生成能力；Content Contract 表示 Agent 与 Python 之间的数据合同；模板版本表示 Word 布局、语义书签和兼容规则。

完整更新记录见 [`../CHANGELOG.md`](../CHANGELOG.md)。

## 2.1 核心变化

2.1 是在 2.0 内容生成链上的课程基础合同收口，不只是模板升级：

- 先形成整门课程 outline，再按完整课程上下文生成逐课内容；
- 正式生产输入默认使用 `content_contract_version: "2.1"`，并兼容读取 Content 2.0；
- 任务开始一次性确认课程基础信息、理论/实践组织、教材、辅助资料和实践任务工单需求；单课默认 2 学时，确认后不再二次打断；
- 引入 `delivery_plan`、课次理论/实践小时、课程级 outline 和 Practice Task Contract V1；
- 将 `course_materials.textbook` 与可引用的 `reference_pool` 分开，教材默认不写入 Word references，逐课只使用 `reference_ids`；
- Python 不再根据 sparse input 或旧固定话术补写教学正文，只负责确定性校验、格式化和模板映射；
- 增加重复 / 相似度、课次 progression、单课主语义连通和 implementation 逐项 coherence QA；
- 评价分数显式限定为 **85–96**，使用 **0.5** 步长，并为 canonical 13 项评价提供逐课备注；
- 支持护理、会计、机械等非 IT 课程，避免固定 IT 场景污染；
- references 使用可核实的 `provided / verified_public` 文献/文档合同；generic 仅可作为文档语义的兼容来源，泛化占位和虚构书目信息均失败；
- 输出采用 candidate → QA → atomic commit，失败不会静默覆盖正式输出；
- 项目级 Full Engine 增加 runtime fingerprint / stale detection，避免新规则配旧 runtime；
- Windows 和 macOS required CI 均实际运行 Lesson Content、Lesson Package 和 Hardening 回归。

## 适用场景

- 按统一模板生成整门课程教案；
- 根据能力图谱、章节任务拆解、课程标准、教材目录或旧教案生成项目化课程；
- 将旧版 `.doc` 或格式不统一的教案整理为 `.docx`；
- 为实训课生成少课时、成果导向、过程评价明确的教学设计；
- 在不改变 Word 模板布局的前提下批量生成具有课次差异和递进关系的教案。

## 建议提供的资料

优先提供：

- 课程名称、专业、授课对象、总课时和每份教案课时；
- 能力图谱、章节任务拆解、课程标准、教材目录或旧教案；
- 固定项目名称、任务名称、输出目录等特殊要求；
- 如不使用内置模板，可提供自定义 DOCX 模板及匹配 manifest。

Skill 会先读取当前会话和已有附件，并在正式规划前一次性集中确认课程基础信息；单课课时默认 2 学时，教材建议确认但不是阻断字段。确认后直接完成资料检索、outline、Content 2.1、Practice Task Contract、QA 和 DOCX，不再询问模板、输出目录或是否开始生成。

正式 DOCX 不写入“资料不足、推断、AI、QA、similarity、confidence”等内部说明。

## 内容与质量流程

默认流程：

```text
读取资料 → 一次性确认课程核心信息
→ 课程级项目 / 任务 outline
→ Lesson Content Contract 2.1 JSON
→ Input Contract QA
→ Content Quality QA
→ 模板校验
→ candidate DOCX
→ 输出保真校验
→ 可选 render smoke
→ atomic commit
→ qa-report.json
```

每课 2.1 内容直接提供：

- 学情分析；
- 三类教学目标；
- 教学内容；
- 重点 / 难点及策略；
- 教学方法、resources 和 `reference_ids`；
- 9 个固定教学实施阶段；
- 评价分数与 13 项 remarks；
- 可预生成的差异化教学反思；
- prior learning、capability stage、deliverable、next bridge 等课次递进信息。

QA 重点包括：

- 重复和高相似度正文；
- 固定骨架换主题词；
- 课次 progression 的真实成果继承和 forward transition；
- task、核心教学内容和 deliverable 是否属于同一主语义链；
- implementation 中实质性条目是否与本课主题一致；
- 机械分数循环、严格单调分数和全同分数；
- reference pool provenance、教材隔离和 Practice Task handoff；
- DOCX 模板、书签、布局和内容保真；
- 输出事务、路径安全和 stale Full Engine。

QA 报告只保留受限诊断片段及稳定 SHA-256，不保存完整输入 JSON 或整段教案正文。

## 模板与兼容

默认模板：

```text
assets/templates/lesson-plan/v1.1.2/template.docx
```

v1.1.2 使用 70 个 Word 语义书签，并在 v1.1.1 基础上将固定评价标签泛化为“职业价值观”和“职业伦理”。

当前兼容：

- v1.0.x：legacy coordinates；
- v1.1.0 / v1.1.1 / v1.1.2：Word semantic bookmarks；
- 旧 compatibility 路径继续保留；
- 自定义模板必须提供匹配 manifest 和真实 SHA-256 fingerprint。

Skill 2.0 **没有把 Word 模板强行改成 v2.0**，因此既有模板布局和历史兼容路径继续保留。

## 安装

### 推荐：让 AI Agent 安装

将下面的提示词交给具备本地文件、Git 和终端权限的 Agent：

```text
请安装当前仓库中的「教案生成器 2.1」：
https://github.com/ArdenZC/codex-work-skills

请阅读 README、根目录 AGENTS.md、教案生成器/简介.md，以及 lesson-plan-docx-generator 下的 AGENTS.md、通用提示词.md 和 SKILL.md。
检查本机依赖后完成安装和安装验证。
如果当前工具是 Codex，优先使用 scripts/install.py。
不要修改源码、模板或 manifest。
```

### Codex 手动安装

Windows PowerShell：

```powershell
python ".\教案生成器\lesson-plan-docx-generator\scripts\install.py"
```

macOS Terminal：

```bash
python3 "./教案生成器/lesson-plan-docx-generator/scripts/install.py"
```

默认安装到：

```text
~/.codex/skills/lesson-plan-docx-generator/
```

目标已存在时默认不覆盖；`--replace` 会备份后替换；`--dry-run` 只显示计划；`--skills-dir <目录>` 可指定 Codex skills 根目录。

Python 依赖见 `lesson-plan-docx-generator/requirements.txt`。安装器不会静默修改 Python 环境；缺少依赖时按 dependency check / 提示安装。

## 多 Agent 兼容

本 Skill 不绑定模型供应商。模型负责理解资料并生成完整 V2 JSON；Python / Word 模板层只做确定性生成和 QA。

项目级 adapter 默认是：

```text
instruction-only adapter install（仅规则 / 指令安装）
```

```powershell
python "lesson-plan-docx-generator/scripts/install_adapters.py" --target-dir "<project>"
```

默认不复制完整 runtime。如果希望目标项目可以直接运行：

```text
.lesson-plan-docx-generator/scripts/generate_lesson_plans.py
```

必须显式使用：

```powershell
python "lesson-plan-docx-generator/scripts/install_adapters.py" --target-dir "<project>" --copy-engine
```

macOS 使用 `python3`。Full Engine 会记录 deterministic runtime fingerprint；旧版或被修改的 runtime 不会与新规则静默混用。

共享 `AGENTS.md`、Claude、Gemini、Copilot 和 Aider 规则使用 namespaced marker，可与其他 Skill 共存。

## 渲染与视觉证据边界

LibreOffice render 只属于 **render smoke**，用于发现空白页、严重转换失败或明显输出异常，不等于 Microsoft Word 原生分页保证。

`visual-inspection.json` 是 Agent 对当前 DOCX / QA 状态进行代表页检查后的 attestation；它不是所检查 PDF / PNG 的加密证明。没有实际人工 / Agent 视觉检查时，不应声称 visual QA 已通过。
