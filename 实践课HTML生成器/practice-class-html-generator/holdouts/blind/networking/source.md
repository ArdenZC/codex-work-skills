# 计算机网络基础：IPv4、局域网观察与路径诊断

## 课程背景

本节面向高职或大专学生。学生接触过基本网络设备和命令行，但 IPv4 与诊断证据的
基础不稳定。上课使用 Windows；机房可使用 `ping`、`tracert`、Wireshark 和 Cisco
Packet Tracer。理论课按 120 分钟准备，随后安排 120 分钟机房实践。

## 本节范围

本节围绕“小型局域网中一台主机如何找到并访问另一台主机”展开，涉及：

- IPv4 地址、网络部分和主机部分；
- 子网掩码与同网段判断的基本方法；
- ARP 将 IPv4 地址解析为局域网中的 MAC 地址；
- 默认网关与简单路由的作用；
- IP 报文中的 TTL 以及它在逐跳转发中的变化；
- Windows `ping` 和 `tracert` 的基本观察；
- Wireshark 中对 ARP、ICMP 和基本 IP 字段的入门观察；
- Cisco Packet Tracer 中查看基础拓扑和连通性。

本节不展开 VLAN trunk、动态路由协议配置、IPv6、复杂 ACL、NAT 配置或网络安全
攻防。实践观察以教师提供的局域网/模拟拓扑为准，真实网络中出现的路径和设备数量
可能不同。

## 概念说明

子网掩码把 IPv4 地址划分为网络部分和主机部分。同一掩码下，判断两台主机是否在
同一子网，不能只比较地址的最后一个数字；应结合掩码计算网络地址。若目标在本地
子网，主机通常需要先知道目标的 MAC；ARP 请求在局域网中寻找这个映射。

如果目标不在本地子网，主机把帧交给默认网关，由路由设备决定下一跳。IP 报文经过
路由器时 TTL 会按跳递减，TTL 耗尽时会产生相应的 ICMP 反馈。`ping` 主要帮助观察
连通性与往返时间，`tracert` 通过逐步变化的 TTL 观察路径上的响应；超时并不自动等于
目标主机关闭，还要结合地址、时间和抓包证据解释。

## 课堂观察素材

可以用以下地址表讨论同网段判断、网关和路径；表中地址只是课堂模拟素材：

| 设备 | IPv4 | 子网掩码 | 默认网关 |
|---|---|---|---|
| PC-A | 192.168.10.21 | 255.255.255.0 | 192.168.10.1 |
| PC-B | 192.168.10.35 | 255.255.255.0 | 192.168.10.1 |
| Server-C | 192.168.20.10 | 255.255.255.0 | 192.168.20.1 |

观察 Wireshark 时，先用协议、源/目的地址和 Info 栏定位一组相关报文，再打开单个
报文检查 Ethernet、ARP 或 IPv4/ICMP 字段。不要把一次抓包中的具体 MAC、接口名或
路由数量当成所有网络都固定如此。

## 命令与工具素材

Windows 中常见的观察入口包括：

```text
ipconfig
ping 192.168.10.35
tracert 192.168.20.10
```

Packet Tracer 中可以通过设备、连线、接口地址和 Simulation 视图观察报文经过的节点；
Wireshark 中可以使用 `arp`、`icmp` 等显示过滤器帮助缩小观察范围。工具输出受拓扑、
接口状态和课堂网络权限影响，命令本身不是对结果的保证。

## 结果讨论

课堂收束时，学生应能把“地址是否同网段”“是否需要 ARP”“是否交给网关”“TTL 和
路径证据说明什么”串成一条解释链，并能区分连通性现象、抓包证据和对原因的推断。
遇到失败时，先检查本机地址/掩码、接口和目标，再选择适当的观察工具，不把所有问题
都归结为一个命令的输出。
