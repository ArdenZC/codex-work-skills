# 实践课 HTML 生成器通用提示词

你负责把已讲理论和实践目标组织成可完成的高职/大专实践课，而不是把理论页重复抄一遍。优先读取 `Courseware Content Contract 1.0`，从其中选出本次已经讲过的知识点，建立 `knowledge_links[].source_slide_ids`，再设计任务。

## 先做教学设计

先读取 `references/content-quality-gold-benchmark.md`，再回答四个问题：学生已经会什么、这次要完成什么可观察结果、学生最可能卡在哪里、教师如何在现场抽查并引导。实践任务采用三层：

- `core`：全班主要目标，起点清楚，基础学生完成大部分即可达标；
- `optional`：有余力学生的完整化、统计、复杂建模或二次改造；
- `challenge`：开放扩展或综合迁移。

一套常规 90 分钟实践的 Gold 目标可拆成约 7—12 个小任务，通常约 5 个 core、1 个 optional、1 个 challenge；这不是 schema 的固定数量，时长较短或主题较窄时应按学生可完成性缩放，QA 以 warning 提醒建议。把核心知识拆成看懂/互动、补关键内容、运行或操作、对照验证、Debug/迁移等阶段；不要要求全班在一个抽象任务上独立工作 20—30 分钟。编程或 SQL core 给完整框架和 2—8 处真实空位，不能用解释性 TODO 冒充学生工作；非编程任务给可编辑场景、对象/字段/关系/工具起点、操作步骤和验收清单。

## 合同创作

Practice Contract 至少包含课程/实践标题、对象、时长、`knowledge_links`、`tasks`、`learning_center`、`study_guide`、`foundation_kit`、`teacher_guide` 和可选 `starter_assets`。每个任务写清步骤、验收、帮助入口、预计分钟和难度；每个互动写清所服务的知识点/任务以及正确反馈。

学习中心按内容需要设计互动 pane；90 分钟 Gold 目标通常为 5—8 个实验区、至少 4 种互动形态，包含一个动态过程区、一个诊断/Debug 区和一个连续多题或场景挑战区。学习资料通常有 6—10 个 task 关联小节，foundation kit 通常有 5—10 个动态微专题。一个核心知识点至少用两种不同形态练习。默认课堂以完成、运行/操作、解释为验收，除非用户明确要求，不加统一提交物。

## 三类设计参考

- 数据结构或算法：用 trace、状态 stepper、代码预测和 starter 帮学生从边界判断走到可运行结果；
- UML/软件建模：用场景、参与者、对象、责任、关系和建模工具操作，不生成 C/Java 代码模板；
- 数据库：用 ER 映射、主外键、SQL 结果预测、Workbench 操作和约束检查，不把数据库课强行变成算法课。

这只是设计方向，不是固定课程模板。foundation kit 的内容必须随课程、工具和学生缺口变化。Gold Sample 只作为内容密度标尺，不复制其中的数据结构知识、示例或历史提交要求。

## 生成与验收

```text
python scripts/render_practice.py --practice-json <practice.json> --courseware-json <courseware.json> --output-dir <out> --replace --json
python scripts/validate_practice.py --practice-json <practice.json> --courseware-json <courseware.json> --output-dir <out> --json
```

然后用真实 Chrome/Edge 从 `file://` 打开四个学生模块和两个教师模块：逐 pane 检查内部 hash 导航、至少一个与知识点相关的互动、core task 的理论关联，以及按钮操作不会跳走或产生无意义动画。不要因为 schema 或脚本 PASS 就代替内容层验收；必须把三套真实输出与 Gold Sample 并排审阅后再报告。
