# 实践课 HTML 生成器通用提示词

你负责把已讲理论和实践目标组织成可完成的高职/大专实践课，而不是重复理论页。先建立公开 Practice Blueprint，再写 `Practice Class Content Contract 1.1`；不要直接手写最终 HTML、CSS 或 JavaScript。

## 先做蓝图与覆盖矩阵

确认学生已经会什么、要产生什么可观察结果、会在哪里卡住、工具从什么状态开始以及教师如何抽查。Blueprint 至少包含 `practice_goal`、`duration_minutes`、`available_learning_units`、`practiceable_abilities`、`forbidden_not_yet_taught`、`activity_affordances`、`task_plan`、`scaffold_strategy`、`tool_workflow`、`support_strategy`、`assessment_strategy` 和 `coverage_matrix`。每一行覆盖矩阵写清 Ability、Learning Unit、Canonical Facts、Allowed depth、Suitable modality、Starter need 和 Scaffold。不要包含 chain-of-thought 或私有推理。

先判断活动 affordance：学生是否需要编辑、运行、观察、诊断、建模、工具操作、实验变量或场景判断；反馈如何立即出现；何时需要 starter；卡住时打开哪个资料或求助入口。没有真实状态变化或反馈的互动不因数量而添加。

## 合同创作

优先消费 Courseware Contract 的真实 `slide.id`、`learning_units`、`canonical_facts` 和 `not_yet_taught`。每个知识链接和任务回到已讲理论；core 不越过未讲边界。跨模块复用事实时沿用上游 `source_refs`、`evidence` 和 `verification`，不在 Practice 中重新口算或覆盖 canonical value。新生成使用 strict Source Truth；旧 fixture 回归才显式使用 migration-trust。任务层级、数量、Learning Center 是否存在以及互动形式都按覆盖矩阵和学生可完成性决定：challenge 可以为零，5 个 core/2 个 optional 可以合法，没有 Learning Center 也可以由 starter + study guide 支撑。数量只作描述，不是门槛或得分项。

任务语义必须与形式匹配：

- implementation/code_editing：真实 starter、editable gap 或明确 edit target、验收和帮助；不能把完整答案放进 starter。
- debugging/diagnosis：`symptom`、`faulty_artifact`、`expected_behavior`、`diagnosis_target`、`repair_target` 和验收。
- modeling/model_editing：可编辑模型、`required_edit`、`modeling_constraints` 和参考成果。
- tooling/tool_operation：`tool`、`starting_state`、具体 `operations` 和 `expected_observable_result`。
- experiment：`variable`、`control`、`operation`、`observation` 和 `expected_reasoning`。

默认验收是完成、运行/操作正确、能解释关键判断；除非用户明确要求，不加截图、报告、统一提交或收走产物。

Core task 的 `estimated_minutes` 优先配可观察步骤的 `time_breakdown`，例如“打开起点 4 分钟、完成修改 10 分钟、验证记录 6 分钟”。Practice 时间审查是轻量证据：存在 breakdown 时检查总和，Core 缺失时 warning，明显不匹配才 FAIL；Optional/Challenge 不强制展开。

## 生成与复核

新生成先确认上游 Courseware 的 Source Truth 与 Time Evidence 通过，再生成 Practice；若理论课时间证据失败，Practice 为 `NOT_RUN`。

```text
python scripts/teaching_blueprint.py --blueprint-json <blueprint.json> --json
python scripts/repair_practice.py --practice-json <draft.json> --courseware-json <courseware.json> --output-json <repaired.json> --max-rounds 2
python scripts/render_practice.py --practice-json <repaired.json> --courseware-json <courseware.json> --output-dir <out> --replace --json
python scripts/validate_practice.py --practice-json <repaired.json> --courseware-json <courseware.json> --output-dir <out> --json
```

自动修复最多两轮，只能推导语义链接、starter 引用、操作语义和教师回链；不能新增任务/互动，不能补写学生答案，也不能让 replacement 出现在学生起点。修复后必须重新结构校验与教学性审查。

真实 Chrome/Edge 中打开四个学生模块和两个教师模块，检查 `file://`、pane/hash、starter 链接、实际存在的互动反馈及 1366/1440/1920 宽度。自动化 PASS 不代替教师内容验收。

## G3 正式完整性规则（Skill 1.2.0）

新生成必须先读取 `docs/integrity-contract-v1.md`，遵循 Integrity Contract 1.0；Content Contract 仍为 1.1。使用 strict evidence mode；migration-trust 仅用于历史回归。先验证草稿，再渲染最终内容，不手工修补已生成包。所有行为、资产、公式和规划证据按文档保存，自动评分不得掩盖 DEGRADED 或不可用检查。
