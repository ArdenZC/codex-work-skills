# Practice Class Content Quality Gold Benchmark

这份参考只抽象内容质量标准，不复制任何一门课程的知识点、案例、代码或历史提交要求。它用于判断生成结果是否已经接近“教师下一次课就敢拿进机房使用”的实践课，而不是替代 Courseware Content Contract 1.0。

## 质量目标

一套 90 分钟左右的实践包应让学生沿着明确的课堂节奏持续推进。每一个阶段都有可观察的结果、理论锚点、卡住时的自助入口和教师可抽查的证据。基础学生靠脚手架完成核心的大部分任务即可达标，中等学生完成全部核心，进度快的学生再进入有余力和提高挑战。

## Gold Sample 的抽象要求

正式 Gold Sample 只作为内容质量参照，不作为课程知识、数据结构、代码或版式模板。并排比较时要学习它的：任务颗粒度（每一小步都有动作和结果）、互动深度（先判断/操作，再得到反馈，再进入下一步）、学习资料密度（概念、例子、检查点和常见错误足够学生自助）、基础补给（按真实卡点组织的微专题）、自助路径（知道卡住时打开什么、检查什么）和课堂节奏（教师能在 90 分钟内推进、巡视、收束）。页面内容密度要达标，但不要把密度误解为一页塞满所有内容。

## 内容密度底线

- Gold 参考的一套 90 分钟实践通常为 7–12 个任务/活动、约 5 个 `core`、1 个 `optional`、1 个 `challenge`；这些是按时长判断的内容建议，不是跨课程的固定 schema 门槛。短课、窄主题或更长课应按学生可完成性缩放，并在 QA 中说明 warning。
- 每个任务至少 3 个具体步骤。核心知识应拆成“看懂或互动 → 填写/操作关键点 → 运行或检查 → 对照验证 → Debug/迁移”中的多个阶段，而不是用一个 30 分钟的大任务替代活动序列。
- 学习中心为 5–8 个实验区，至少覆盖 4 种互动形式；至少有一个动态状态/过程区、一个诊断或 Debug 区、一个连续多题/场景挑战区。互动必须改变学生的判断、操作或下一步路径。
- 互动数量达到 5–8 个并不自动代表高互动质量。90 分钟实践建议至少有 2 个状态/多步互动、至少 1 个连续诊断或多案例 Debug；参数或状态变化要带来即时反馈，选项不应只是把多数时间切成单选题。数量只是上限提示，互动深度和与任务的连接优先。
- 学习指南为 6–10 个小节，按本次理论顺序组织。每节要有本课使用的同一类数据/对象/公式/代码或工具步骤、检查点、常见错误，并链接到具体 task。
- 基础工具包为 5–10 个课程动态微专题，覆盖本次实践会用到的语言、工具、语法、建模动作、SQL 子句或排错动作；每个微专题都应说明何时打开和如何自检。
- 每个核心知识点至少在两种不同活动形态中出现，例如状态追踪 + 关键位置填写、模型分类 + 消息排序、结果预测 + 查询诊断。不要只把同一知识点重复成几道单选题。

## 信息架构与页面阅读

- 四个学生模块和两个教师模块是完整主页面；任务、互动、资料小节和基础微专题在模块内用 pane 聚焦并可互相导航，不再为每个对象拆出动态详情 HTML。
- 模块导航只保留摘要、预计时间、层级和下一步；当前 pane 只承载一个焦点，正文采用可读的单列结构，避免厚重左边框和复杂多列堆叠。
- 每个模块必须能通过 hash/导航切换 pane、回到目录、前往上一项/下一项，并给出标题、预计时间和帮助入口。学生页不应出现原始合同版本、task/slide ID、互动语义类型或教师链接。
- 离线 HTML 包是六个可导航的模块页；“不是一个 HTML 文件”不是缺陷，只要主页面和 pane 导航在 `file://` 下有效。

## 脚手架与可完成性

- 编程或 SQL 核心 starter 保留完整上下文和可运行的外壳，但必须留下 2–8 个真实需要学生改动的关键位置。`TODO` 不能只是解释已经写好的正确行；占位值、错误但可执行的条件、空的关键表达式或可编辑字段必须影响结果。
- 非编程核心任务提供等价的可编辑起点，例如 draw.io 初始模型、字段/关系槽、工具操作卡、带错误的模型或可复核的结果表；不能只给一张概念说明。
- 每个核心任务都要有可观察验收与参考结果。默认课堂标准是完成、运行/操作正确、能解释关键判断；除非用户明确要求，不把截图、报告、统一提交或收走产物写成默认门槛。
- 起点文件必须能从学生页用相对链接取得；文本预览是可选的，draw.io 和其他二进制/可编辑文件不得把原始 XML 或内部序列化内容直接展示给学生。教师参考要能直接用于课堂核对：完整代码/SQL 答案、预期结果与解释、等价写法和常见错误，以及建模/工具任务的可见参考模型或等价操作结果。

## 教师可用性

`teacher-guide.html` 要能直接支持 90 分钟授课：节奏、每个核心任务的巡视点、卡住时的追问、常见错误干预、弱基础路径、快进度路径和收尾抽查都应具体。`teacher-reference.html` 独立给出逐任务答案或参考成果、关键步骤、可接受变体、错误和验收依据。

## 并排验收

自动化通过只说明结构、链接、renderer 控件和终止状态没有明显错误。内容验收还必须把真实生成的学生任务、学习中心、学习指南、基础工具包和教师页面与 Gold Sample 并排打开，逐项比较任务颗粒度、互动可操作时长、资料密度、自助路径、课堂节奏和参考成果覆盖。若页面“结构正确但几分钟就做完”，仍然判为内容不通过。**自动化 PASS 不代表内容验收通过，等待真实 HTML 内容验收。**
