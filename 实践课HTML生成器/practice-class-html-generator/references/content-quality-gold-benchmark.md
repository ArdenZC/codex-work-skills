# Practice Class Content Quality Gold Benchmark

这份参考只抽象内容质量标准，不复制任何一门课程的知识点、案例、代码或历史提交要求。它用于判断生成结果是否已经接近“教师下一次课就敢拿进机房使用”的实践课，而不是替代 Courseware Content Contract 1.0。

## 质量目标

一套 90 分钟左右的实践包应让学生沿着明确的课堂节奏持续推进。每一个阶段都有可观察的结果、理论锚点、卡住时的自助入口和教师可抽查的证据。基础学生靠脚手架完成核心的大部分任务即可达标，中等学生完成全部核心，进度快的学生再进入有余力和提高挑战。

## 内容密度底线

- 任务/活动通常为 7–12 个；至少 5 个 `core`、1 个 `optional`、1 个 `challenge`。
- 每个任务至少 3 个具体步骤。核心知识应拆成“看懂或互动 → 填写/操作关键点 → 运行或检查 → 对照验证 → Debug/迁移”中的多个阶段，而不是用一个 30 分钟的大任务替代活动序列。
- 学习中心为 5–8 个实验区，至少覆盖 4 种互动形式；至少有一个动态状态/过程区、一个诊断或 Debug 区、一个连续多题/场景挑战区。互动必须改变学生的判断、操作或下一步路径。
- 学习指南为 6–10 个小节，按本次理论顺序组织。每节要有本课使用的同一类数据/对象/公式/代码或工具步骤、检查点、常见错误，并链接到具体 task。
- 基础工具包为 5–10 个课程动态微专题，覆盖本次实践会用到的语言、工具、语法、建模动作、SQL 子句或排错动作；每个微专题都应说明何时打开和如何自检。
- 每个核心知识点至少在两种不同活动形态中出现，例如状态追踪 + 关键位置填写、模型分类 + 消息排序、结果预测 + 查询诊断。不要只把同一知识点重复成几道单选题。

## 脚手架与可完成性

- 编程或 SQL 核心 starter 保留完整上下文和可运行的外壳，但必须留下 2–8 个真实需要学生改动的关键位置。`TODO` 不能只是解释已经写好的正确行；占位值、错误但可执行的条件、空的关键表达式或可编辑字段必须影响结果。
- 非编程核心任务提供等价的可编辑起点，例如 draw.io 初始模型、字段/关系槽、工具操作卡、带错误的模型或可复核的结果表；不能只给一张概念说明。
- 每个核心任务都要有可观察验收与参考结果。默认课堂标准是完成、运行/操作正确、能解释关键判断；除非用户明确要求，不把截图、报告、统一提交或收走产物写成默认门槛。

## 教师可用性

`teacher-guide.html` 要能直接支持 90 分钟授课：节奏、每个核心任务的巡视点、卡住时的追问、常见错误干预、弱基础路径、快进度路径和收尾抽查都应具体。`teacher-reference.html` 独立给出逐任务答案或参考成果、关键步骤、可接受变体、错误和验收依据。

## 并排验收

自动化通过只说明结构和链接没有明显错误。内容验收还必须把真实生成的学生任务、学习中心、学习指南、基础工具包和教师页面与 Gold Sample 并排打开，逐项比较任务颗粒度、互动可操作时长、资料密度、自助路径、课堂节奏和参考成果覆盖。若页面“结构正确但几分钟就做完”，仍然判为内容不通过。
