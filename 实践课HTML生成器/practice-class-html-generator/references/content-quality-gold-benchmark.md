# Practice Class Content Quality Gold Benchmark

这份参考只抽象内容质量标准，不复制任何课程的知识点、案例、代码或历史提交要求。它用于教师判断实践课是否可直接进机房，不是任务/互动数量模板，也不替代 Contract 1.1。

## 判断顺序

先看 coverage matrix 是否把已讲 learning unit、canonical fact、可观察能力和允许深度连起来；再看每个活动是否有合适 affordance、起点、反馈、支架、验收和教师观察证据。课程可选择很少的任务、没有 challenge 或没有 Learning Center，只要这条证据链完整；数量不加分。

## 内容质量

- 每个任务拆成学生能执行的动作和结果，避免一个无法在课堂推进的大任务。
- implementation/code_editing 要有真实可编辑 starter 或 edit target；debugging 要有症状、错误产物、期望行为、诊断目标和修复目标；建模、工具和 experiment 任务要分别提供可编辑模型、工具起点/操作/观察结果或变量/控制/推理。
- 学习中心只在能带来即时反馈、状态变化、连续诊断、多步操作或场景判断时加入。每个互动都回链到具体知识或任务，检查后才显示反馈或答案。
- 学习指南、foundation kit 和帮助入口要按实际卡点提供“何时打开—检查什么—如何继续”，不是按目录数量填充。
- 核心任务要有真实可取得的起点和可核对参考成果；学生 starter 不得出现完整 replacement、教师答案或内部元数据。

## 教师可用性

教师页应有课堂节奏、巡视点、卡住时的追问、常见错误干预、弱基础路径、快进度路径和收尾检查。教师参考要能直接核对代码、查询、模型、工具结果或等价变体。

## 并排验收

自动化通过只说明结构、链接、renderer 控件和终止状态没有明显错误。内容验收还要把真实生成的学生模块、学习中心、学习指南、基础工具包和教师页面与原始资料并排打开，检查任务是否做得出来、互动是否有实际反馈、资料是否足以自助、节奏是否可授课以及参考成果是否完整。页面“结构正确但几分钟就做完”仍是教学性问题。

## G3 质量边界

教师逐字稿以可以直接朗读的 120–160 字/讲解分钟为默认目标，80 字只是最低边界。必须解释当前页的具体内容，重复扩句不算容量。教师参考的可执行答案必须有行为证据；课堂起点必须形成完整项目/输入资产包；公式绑定当前字段并给实际结果。人工验收检查这些内容，不以结构或语法 PASS 代替。
